Important function contracts

QuickHeader.build reads current preferences and effective theme. A theme press passes the opposite displayed brightness to PreferencesController.update; language selection passes the selected language without a download. Errors show a message. The controller updates the screen immediately, serializes database writes, and rolls back the latest failed write. Callers are the header and Settings.

KnowledgeRepository.search receives a query, language, filters and page number. It removes only recognized question prefixes and punctuation, then calls AppDatabase.rankedArticles. The database performs bounded FTS5 retrieval ordered by BM25; a page reads at most page size plus one rows. Output is KnowledgePage, including hasMore. No network call occurs. SQL failures propagate to Library's error state. Library debounces 250 ms and changes the FutureBuilder key when its query context changes, preventing an older result from replacing a newer one.

WikipediaService.request accepts only supported Wikipedia language hosts and bounded API responses. It has connection/read deadlines, rejects redirects and returns decoded JSON or an error. convertPage parses HTML without a browser, removes executable elements and builds text sections plus local-link targets. It retains revision and license attribution and marks the record external. save checks Wi-Fi preference, budget and free space, then atomically replaces only that source-qualified page in SQLite. Existing bookmarks are separate. Images, multimedia and interactive elements are explicitly omitted; saved pages must not be used for food identification. hasUpdate makes an explicit online revision check when pressed. No background polling occurs.

AppDatabase migration 2 to 3 adds archives and download_jobs metadata tables. It does not rename, drop or rebuild bookmarks, preferences, places or packs. The archive/job tables are preparatory; their presence is not evidence of native background-download support.

ZimReader.request and asset run on worker isolates. The C ABI opens an archive on demand, bounds result count and entry size, and returns owned buffers. Dart copies bounded results and releases native memory in finally blocks. Missing archives, entries and indexes return errors. See native prototype.

Content and recovery

Edit an authored language file, run python3 tools/practical_content.py, then python3 tools/check.py. The compiler never manufactures missing translations or grants reviews. registry/content_coverage.json records actual coverage. Article review fingerprints bind approvals to exact content; changing steps, media metadata or cautions invalidates approval. Required food photos need exact hashes as well as real-photo provenance, attribution and specialist review.

If an individual page save fails, keep the existing SQLite record and retry when space/network is available. There is no partially ready reference record. These small page saves restart rather than resume. Existing optional-pack downloads retain their separate resumable verified-install workflow.

Do not downgrade an app database by changing PRAGMA user_version. For app-update recovery, preserve the support directory and restore a compatible app/database backup. Optional content rollback and app database rollback are different tasks.

App flow

Dooms Day App is an offline reference application. Its five destinations are Emergency, Library, Map, Downloads, and Settings. Nearby messaging is phase two.

Startup

Entrypoint → initialize Flutter → persistent application support directory → open Drift database → migrate schema → load essential articles and language strings → load preferences → override Riverpod providers → display the application.

Production uses main.dart. Development uses main_development.dart. The production import graph never imports lib/development. The development application has a different native application identifier and storage directory.

Reading and searching

User query → LibraryScreen → AppDatabase.articles → SQLite FTS5 and bounded title matching → ArticleTile → ArticleScreen. Medicine aliases are indexed with article text. Search never calls a server. Search queries are parameterized and FTS tokens are quoted. A missing translation can be opened explicitly in English.

Bookmark → AppDatabase.toggleBookmark → independent bookmark table → revision provider invalidation → updated bookmark icon. Removing a pack removes its articles and search records, but not bookmarks.

Installing a pack

User requests catalog refresh → HTTPS catalog → select pack → check Wi-Fi preference, budget and free space → download to .part → verify length and SHA-256 → inspect ZIP paths and content → immutable version directory → database transaction activates articles and installed-pack record.

Failure before activation keeps the previous pack active. Cancellation retains the partial file. Previous version directories are retained for recovery and count toward storage. No automatic content expiry makes an installed emergency handbook unreadable.

Navigation

Open Map → verify local pack files → rewrite style to local archive and assets → MapLibre renderer. Tap Locate → request foreground permission → get one GPS fix → show coordinates and accuracy. Compass subscriptions run only while the map screen is mounted and the app is in the foreground.

Saved places are independent database records. Distance is great-circle distance; destination bearing is relative to true north, while the sensor displays magnetic heading. There is no automatic route calculation or live facility status.

Module boundaries

Screens call repositories and services through providers. Database code does not import screens. Pack installation does not mutate preferences or bookmarks. Device-specific storage operations use the org.fieldkit/storage method channel.

Future nearby communication belongs in a separate service with consent, peer verification, delivery acknowledgements, and real Android/iPhone compatibility tests. It is not implemented in this release.

Build and tools

Pinned tools

Flutter 3.44.4 and Dart 3.12.2 are pinned in .flutter-version. Direct dependencies are pinned in pubspec.yaml; transitive versions are committed in pubspec.lock. Python 3.10+ runs repository tools. Xcode project editing uses xcodeproj 1.27.0.

The Android project uses its checked-in Gradle wrapper and requires JDK 21 (MapLibre's native compilation requirement) and Android SDK 36. Native iOS builds require macOS, Xcode, and plugin dependency resolution. Do not infer store submission readiness from a successful debug build.

Minimum supported OS: Android 7/API 24 and iOS 15. The iOS minimum reflects the supported deployment range of the installed Xcode 27.1 SDK, independently of the submission SDK requirement.

Simulator builds target arm64 on Apple Silicon (use an x86_64 override on an Intel Mac). Use --platform android or --platform ios on a platform-specific CI worker. Simulator app bundles are preserved separately in build/artifacts/ so one flavor cannot overwrite the other.

SQLite schema

articles contains a JSON body plus language, ID, category, level and pack index. article_search is the FTS5 index. bookmarks, preferences, places, and checklist contain user-owned data. packs records the active immutable directory, version, type, installed size and archive hash.

Schema version 3 adds archives and download_jobs metadata tables. Version 2 added checklist storage. Migrations are explicit in AppDatabase.migration and tested against version-one and version-two fixtures. Never delete a database to hide a migration failure.

Pack contract

A catalog has schema_version 1 and a packs array. Each pack has id, title, version, language, kind (content or map), URL, SHA-256, exact compressed and installed byte counts, and description. HTTPS is required; redirects are rejected.

An archive contains manifest.json and either articles.json plus illustrations, or map.pmtiles, style.json, and any local glyph/sprite assets. The manifest contains identity, version, kind, and hashes of its data files. Paths are relative; symlinks, executable files, traversal and duplicate paths are forbidden.

Map style sources must reference pmtiles://map.pmtiles. Glyphs use glyphs/{fontstack}/{range}.pbf, sprites use sprites/sprite. Map fonts are separate from Flutter interface fonts. Include the glyph ranges used by your map labels.

Test records

Feature IDs use F01 etc.; cases use T01 etc. Results have a build fingerprint, timestamp, platform, status and evidence. Status is passed, failed, blocked or not_run. The test dashboard imports only matching-build records. Human clinical review is separate from automated content structure validation.

See upgrade function contracts for question normalization, ranked search, Wikipedia saves, the rich reader, native example export and the isolated ZIM prototype.

Tests

Automated runs

Use python3 tools/run_tests.py. It runs Python validation tests, Flutter tests, and records observed outcomes in registry/results.json. Never mark a case passed because its test merely exists. A mixed or physical-device case remains incomplete until its manual evidence is recorded.

Flutter tests cover SQLite search, data persistence, schema migration, pack validation, update rollback, navigation mathematics, and large-text UI rendering. Python tests cover content publication rules, documentation, registry mappings, and release blockers.

Test Center's UI tab can open isolated previews for missing compass, denied GPS, and an unavailable catalog. These fixtures never request device permissions. The Diagnostics tab probes the real native compass with a five-second timeout; availability does not establish accuracy. Results accept evidence notes and matching-build automated JSON. They do not constitute medical review.

First launch and cold restart are mixed cases: SQLite checks provide automated evidence, but their acceptance status remains not run until the complete airplane-mode device scenario is recorded. automated_status retains partial evidence without upgrading a mixed case to passed.

Physical-device matrix

Test at least an older supported Android phone, a recent Android phone including 16 KB page-size compatibility, an older supported iPhone, and a recent iPhone. Include a device without a compass where possible. Simulators do not verify magnetometer behavior, battery use, background restrictions or real radio range.

For every run record platform, model, OS, build fingerprint, app flavor, network state, steps, expected result, observed result, screenshots/logs and tester.

Download interruption and cancellation: T08 / T09

Serve a valid pack from an HTTPS test host supporting Range requests. Start a download, interrupt Wi-Fi, restart the app and resume. Check response ranges, final hash, installed count and readable content. Repeat with a server that ignores Range and with an incorrect Content-Range. Cancellation must leave a partial download rather than a ready pack. Disable Wi-Fi with Wi-Fi-only enabled and check that no cellular download continues.

Low storage and safe updates: T12

Use a disposable emulator/device profile. Constrain free space below the required archive plus expanded size and update workspace. Attempt a download. The old version must still open. Then restore space and retry. Do not fill a personal device as a test.

Map, location and compass: T06 / T13 / T15

Install a reviewed regional map with glyphs and sprites. Disable networking and cold-start. Pan, zoom and inspect non-Latin labels; verify no network font fetch. Clear disposable caches without removing application data and repeat. Delete one pack resource in a development fixture: verification must fail.

Deny location once and permanently; disable system location; test indoors without a GPS fix. Check sensor absence and calibration messages. Move after obtaining a fix and confirm the displayed timestamp makes stale data apparent.

UI and accessibility

Exercise all screens in light/dark themes, all nine languages and at 200% text. Use TalkBack and VoiceOver. Check contrast, reading order, focus, labels, and touch targets. Core automated layouts are a starting point, not complete accessibility certification. Capture visual baselines only after reviewing them.

Production inspection: T18

Run tools/check.py to verify the production import graph. Inspect the actual APK, AAB and IPA assets: development registry and fixtures must be absent. Launch the production binary and verify there is no Test Center or reset route. Development and production must install side by side without sharing data.

Performance

Record store-download and installed sizes separately. Target less than 100 MB for the store download, excluding optional packs. Measure cold startup, search with large installed libraries, map memory, and battery use on representative hardware. Record results rather than inventing thresholds met by unmeasured code.

Troubleshooting

Empty production library

Cause: no approved starter content. Check review_status and translation_review in the content files. Production intentionally filters draft material. Use the development build for review; do not bypass the publication gate to ship drafts.

Search misses a topic

Check selected language and whether the pack is installed. Inspect the article's title, aliases and keywords. Run the alias test in Test Center or flutter test test/database_test.dart. AppDatabase.installArticles updates both the article table and FTS index in one transaction.

Blank map

Check that a map pack is installed, not merely partially downloaded. Verify files in Downloads. Inspect style source names, archive schema, glyph paths and sprites. All references must resolve locally. Read the map's coverage bounds before assuming a blank area is a rendering bug. Native rendering needs device evidence.

Download fails

Read the displayed reason: network preference, HTTPS response, budget, device free space, checksum, content review, or archive structure. Partial bytes remain for resumption. A checksum failure deletes the invalid partial file. Do not mark a pack installed by editing its database row.

Update leaves an old directory

Old versions are retained intentionally and counted in disk usage. The active directory is in the packs table. Preserve it. Use the documented recovery process to reactivate a previous validated package; do not delete the database.

Text clips or a script is missing

Check the selected font family in FieldkitApp and font assets in pubspec.yaml. Run the multilingual widget test. Check Directionality and avoid fixed text heights. A font can be present without having every glyph; inspect real devices.

Permission denied or compass unavailable

These are supported states. Handbook reading does not require device permissions. Location is requested by NavigationService.locate after the user's action. A missing magnetometer cannot be repaired in software.

How to change a screen

Locate its feature in the Features tab, edit the corresponding widget, run its tests, test large text and error states, then regenerate this guide.

How to change search

Edit AppDatabase.articles or article aliases. Keep query parameters and quoted FTS tokens. Add a regression case for the search that previously failed.

How to add a feature

Add a module with a provider boundary, register the feature and acceptance cases, document its inputs/outputs and permissions, and update store disclosures if its data flow changes. Keep feature-specific test fixtures inside development code.

Content and languages

Current material

The bundled starter material is original draft editorial content. It covers all requested categories in English and provides preparation/lost-person starter cards in all nine languages. Expanded translations, specialist illustrations, clinical review and regional foraging catalogs remain outstanding.

General decorative illustrations are not anatomical or plant-identification evidence. Add reviewed explanatory illustrations when teaching detailed procedures.

Add or edit an article

Edit essential.json for bundled content, or create articles.json in a separate pack directory. Use a stable ID; translated versions share the ID but have different language codes. Include title, summary, category, level, audience, region, prerequisites, sections, cautions, sources, license, illustrations, update date and review fields.

Run python3 tools/check.py. A changed medical/technical article or translation must return to draft until reviewed. Do not copy source content or artwork without checking reuse rights. Document the actual reviewer and reviewed version.

Use python3 tools/review_digest.py assets/content/essential.json to identify the exact text and metadata version under review. After independent approval, record that value in reviewed_content_sha256 with the reviewer and review date. The command only computes a fingerprint; it never approves an article. Publication and production installation reject changed content whose fingerprint no longer matches. Illustration bytes also need independent review and must be covered by the published pack's asset manifest.

tools/seed_content.py is a development seed generator: rerunning it overwrites the starter files and resets them to draft. Do not use it to publish approved editorial work.

Add an illustration

Use an original or appropriately licensed SVG, PNG, JPEG or WebP. Keep text out of the illustration where possible and use translated captions. Add its relative path to the article. For clinical, water-treatment, mechanical, or identification diagrams, obtain subject review of the image as well as the text.

Add or correct a language

Edit the matching file in assets/i18n. Preserve all English keys. Add translated articles and obtain independent translation review. For a new locale, add its code and display name in models.dart, a supported bundled font, locale support, and tests. Interface changes require an app update; content translations can ship as packs. Do not silently present English as a completed translation.

Build an optional content pack

python3 tools/publish_pack.py --source path/to/reviewed-pack \
  --output build/water-en.zip --id water-en --version 1.0.0 \
  --language en --kind content --url https://YOUR_HOST/water-en.zip

The tool writes an archive and catalog-entry JSON. Draft fixtures require the explicit --draft flag and are rejected by the production installer. Upload reviewed archives and the catalog to HTTPS storage supporting Range requests. No hosting account or published endpoint is supplied by this repository.

Map packs

Create a regional PMTiles extract from licensed open data, preserving attribution. Supply a MapLibre style matching its source layers and all glyphs/sprites needed for offline labels. Use --kind map with the same publishing tool. Test coverage, labels and pan/zoom offline on both platforms before publishing. Do not use a general-purpose public tile server for bulk downloads without permission.

Corrections and rollback

Publish a new immutable version with a fresh hash. Never replace bytes at an existing version URL. Content and user state are separate. Keep previous reviewed archives available to republish a corrective version. An application rollback requires a compatible store update; database downgrades are not automatic.

Practical expansion and regional food

The 48 English practical drafts are authored in content/practical/en.json and compiled by python3 tools/practical_content.py. Add actual translations in the corresponding language files; never substitute English text under another language code. The compiler records actual counts in registry/content_coverage.json.

Six regional food editorial manifests live in content/food. They are not shipped identification instructions. Publication requires real licensed photographs, exact media hashes, captions, attribution, specialist and photo reviewer identities/dates, and separate translation review records. Both Python publishing validation and runtime pack admission enforce required-photo checks.

See upgrade status for the remaining authored content and native archive work.

Store release

The repository is not ready for public medical or emergency reliance. Draft content and unverified device behavior are explicit release blockers.

Gate and evidence

Run python3 tools/release.py. It produces build/release-readiness.json and exits unsuccessfully while prerequisites are missing. Record evidence in registry/release.json, registry/policies.json, and registry/results.json. Never set a checkbox merely to obtain a successful exit.

Official requirements and the last verification date are in the Release tab. Recheck those URLs for every submission. Store policies and SDK requirements change.

Before external testing

  • Confirm publisher identity, application IDs, developer-account type and target regions.
  • Configure release signing securely and preserve recovery access.
  • Review the generated original Dooms Day App icon and confirm final branding.
  • Obtain expert and translation review and confirm content/map/font licenses.
  • Host a complete public privacy policy and support page at working HTTPS URLs.
  • Publish a verified content catalog with reviewer-accessible sample packs.
  • Audit plugin permissions and privacy manifests against actual binary behavior.
